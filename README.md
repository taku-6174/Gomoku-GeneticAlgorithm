# 五目並べ AI × 遺伝的アルゴリズム

**「五目並べ AI を自作し、遺伝的アルゴリズム（Genetic Algorithm; GA）で自動的に強化する」** ことを目的とした研究・実装プロジェクトです。

本プロジェクトは、**九州大学芸術工学部メディアデザインコース（三年次編入）への出願ポートフォリオ** として制作しました。

---

## プロジェクト概要

五目並べ AI の強さは、評価関数の重みによって大きく変わる。しかし「どの重みが最適か」を人間が手動で探索するには限界がある。そこで本プロジェクトでは、**遺伝的アルゴリズム（GA）を用いて評価関数の重みを自動最適化する** というアプローチを採用した。

GAを導入したことで、最終的に進化個体は初期個体に対して **先手98% / 後手80% / 合計89%** という勝率を達成した。

---

## なぜ遺伝的アルゴリズムなのか

一般的な五目並べ AI の実装は、大きく2つに分類される。

**① ルールベース（ミニマックス+αβ枝刈り）**
評価関数を人間が手動で設計し、探索で最善手を決める方法。実装例が多く手法が確立されている一方、「どの重みが最適か」は人間が手動で調整するしかない。

**② 強化学習・ニューラルネット（AlphaGoの手法など）**
大量の対局データから自己学習させる方法。本格的だが実装が複雑で、計算資源も大量に必要になる。

本プロジェクトは **この2つの中間** に位置するアプローチを採用している。評価関数の構造（活四・フォークなど）は人間が設計するが、**各パターンの重みの最適化はGAに任せる** ことで、手動調整の限界を超えた自動最適化を実現した。

また、定石パターン（浦月・花月・名月・水月など）は **意図的に組み込んでいない**。定石は人間の知識をコードに手動で埋め込むアプローチであり、本プロジェクトのテーマである「GAによる自動学習のみでどこまで強くなれるか」という方向性と異なるためである。定石を組み込むと強さの向上がGAの効果なのか定石の効果なのかが切り分けられなくなる。**GAのみで89%という勝率を達成したことは、人間の知識を与えずとも自動最適化によって強いAIが獲得できることの証明** として捉えられる。

なお、`engine.py`で実装している活四・眠四・活三・フォークなどのパターン評価は定石とは異なる概念である。これらは「現在の盤面でどのパターンが形成されているか」をその場で判断するルールであり、「序盤にどこへ打つべきか」という定石の知識とは別物である。

## 目標

- 初期状態の五目並べ AI（手作業で設計した評価関数）よりも明らかに強い **「進化個体」** を作ること
- 五目並べが理論上「先手必勝」とされる性質を踏まえ、先手番ではほぼ負けない AI・後手番でも簡単には負けない AI を目指してパラメータを最適化すること
- その過程を通じて、**評価関数の設計・探索アルゴリズム・GAの設計** を統合的にデザインし、メディアデザインとしてもわかりやすく可視化・提示すること

---

## 遺伝的アルゴリズムの仕組み

GAでは「評価関数の重みセット」を1つの **個体** として扱う。進化の流れは以下の通り：

```
① 初期集団の生成
   基準個体の重みの±10%以内でランダムに12個の個体を生成

② 適応度（fitness）の評価
   各個体を常に先手として対戦させ、勝率(%)をfitnessとする
   対戦相手: 基準個体×3 + Hall of Fame上位2体 + 同世代の仲間3体

③ 選択・交叉・突然変異
   トーナメント選択で親を選び、重みを50%の確率で混ぜ合わせて子を生成
   突然変異: 各重みに±15%の乗算変異を確率20%で適用（乗算方式により重みがマイナスにならない）

④ 次世代へ
   上位2体はエリートとしてそのまま残し、30世代繰り返す
```

**先手専用GAの設計:** 個体は常に先手（player1）として対戦・評価する。先手・後手混在の評価では「勝った理由が先手有利なのか重みが良いのか」が曖昧になる問題を解消するためである。結果として、先手専用GAで育てたにもかかわらず **後手でも80%という勝率を達成した**。これは先手で勝つために進化した攻撃的な重みが、後手でも普遍的に機能したと解釈できる。

## 試行錯誤の過程（ver1 〜 final）

本プロジェクトは ver1 から final まで **8つのバージョン** を経て完成した。GAが機能しなかったり、変更が逆効果になったりしながら改良を重ねた過程も記録として残している。

| バージョン | 合計勝率 | 主な変更点 |
|-----------|---------|-----------|
| ver2 | 43% | GAの初期実装（初期個体より弱い） |
| ver3 | 61% | fitnessを勝率%に変更・評価関数拡張 |
| ver4 | 76% | 局所解対策・変異幅拡大 |
| ver5 | 66% | 試合数増加・対戦相手多様化 |
| ver6 | 49% | 並列化・HoF・加算変異（逆効果） |
| ver7 | 78% | engineの大規模拡張 |
| ver8 | 34% | Numba・depth=3（大幅低下） |
| **final** | **89%** | **先手専用GA・乗算変異・engine整理** |

詳細は `changelog.md` を参照。

## アプローチ概要

**ゲームエンジン（`engine.py`）**
クラス `GomokuAnalyzer` が 15×15 の五目並べを管理する。活四・眠四・活三・フォーク（三三・四三・四四）などのパターンベース評価関数を実装し、αβ枝刈り付きミニマックス探索で最善手を探索する。評価関数の重みはGA側から自由に書き換えられる構造になっており、重みの違いが実際のゲームの行動の違いとして現れるよう設計されている。

**遺伝的アルゴリズムによる重み最適化（`ga_manager.py`）**
個体 = `GomokuAnalyzer` の評価関数の重みセット（15種類）。各個体を並列対局させ、勝率をfitnessとして世代を重ねることで重みを自動最適化する。最良個体の重みは `best_weights.txt` として保存され、GUI や別スクリプトから再利用可能。

**インタラクティブな AI 解析ツール（`main.py`）**
PyGame で盤面を描画し、人間 vs AI・AI vs AI・異なる重みを持つ AI 同士など複数のモードで対戦できる。各マスに評価値を色と数字で重ねて表示することで、**AI がどの手をどれくらい高く評価しているかを視覚的に確認できる。**

**進化前後の比較評価（`evaluate_evolution.py`）**
初期個体と進化個体を100試合対局させ、先手・後手それぞれの勝率を統計的に比較する。

## このプロジェクトで示したいこと

- ゲームルールの理解から、評価関数の設計・探索アルゴリズム（ミニマックス＋αβ枝刈り）・遺伝的アルゴリズムによるパラメータ最適化・インタラクティブな可視化UIのデザインまでを **一貫して自分で設計・実装** していること
- 「AI が何を考えて打っているのか？」を、単なるブラックボックスではなく、**視覚的・インタラクティブに体験できるメディア作品** として提示していること
- 完全解（先手必勝戦略）までは到達していないものの、**初期 AI よりも明確に強いプレイスタイルが GA によって自動的に獲得されていくプロセス** を、データとビジュアルでわかりやすく示していること
- ver1からfinalまでの **失敗と改善の過程を記録・考察** することで、設計判断の根拠と思考プロセスを提示していること

## 環境・実行方法

Python 3.12以降、主要ライブラリ: `pygame` / `numpy` / `matplotlib` / `numba`（任意）

```bash
# GUI で AI の思考を可視化しながら対局
python main.py

# 遺伝的アルゴリズムで重みを進化させる（約30世代）
python ga_manager.py

# 進化個体と初期個体を100試合対局させて勝率を評価
python evaluate_evolution.py
```
